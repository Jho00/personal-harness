# Проверка технического выбора

Выдели решение, задачу и ограничения, которые на него влияют. Если в разделе несколько решений, оцени каждое отдельно. Для каждого выбора технологии, библиотеки, метода или архитектуры выпиши критерии, которые использовал автор, и привяжи их к конкретному месту в тексте.

## Оценка критериев

Оцени каждый критерий как сопоставимый или требующий конкретизации. Сопоставимый критерий позволяет сравнить варианты по одной метрике, шкале или проверяемому условию. Для расплывчатой формулировки предложи конкретную замену.

| Формулировка | Что можно проверить |
| --- | --- |
| «Быстрее» | p95 задержки обработки при одинаковой входной нагрузке, размере данных и условиях замера |
| «Удобнее» | Время или число действий при выполнении заданной задачи в одинаковых условиях |
| «Документация лучше» | Возможность восстановить обработку после сбоя по инструкции |
| «Поддерживает транзакции» | Наличие нужной гарантии в указанной версии и режиме работы |

Отдельно оцени доказательства. Замер одного варианта описывает этот вариант. Сравнение требует данных по альтернативам в сопоставимых условиях. При недостатке данных предложи способ проверки или более узкий вывод. Результат привязывай к измерению или источнику, а целевое число обозначай как требование.

## Рубрика MADR

Для существенного архитектурного решения проверь следующие части. Выбор относится к архитектуре, если его пересмотр заметно затрагивает устройство системы, сроки или стоимость изменений. Для локального выбора достаточно контекста и сравнения по уместным критериям.

| Часть решения | Что проверить |
| --- | --- |
| Контекст и проблема | Задача, ограничения и причина, по которой потребовалось решение |
| Критерии выбора | Драйверы и способ сравнения альтернатив |
| Рассмотренные варианты | Реальные альтернативы и доступные сведения по каждой |
| Итог | Выбранный вариант, связь с критериями и причина выбора |
| Последствия | Преимущества, ограничения и принятые компромиссы |

Для отдельного ADR проверь, что запись посвящена одному решению и содержит статус, дату и участников принятия решения. При подготовке ADR используй статусы `proposed`, `accepted`, `rejected` или `deprecated` в соответствии с состоянием решения.
