# Общий журнал

Зависимость помощника `scripts/usage_log.py`: уже установленный Python 3.9+ со стандартной библиотекой. Он не ходит в сеть и ничего не устанавливает. Относительный путь указан от каталога установленного скилла, а не текущего проекта. Если Python отсутствует, согласуй установку; до этого выдай результаты и подготовленные записи в ответе, но не заявляй, что они сохранены.

## Где хранить

По умолчанию: `~/.local/share/personal-harness/tool-finder/` на компьютере, где запускается скрипт. Это один общий журнал для разных задач и проектов одного пользователя. `TOOL_FINDER_LOG_DIR` или аргумент `--log-dir` перед подкомандой задают другой постоянный каталог. Не помещай журнал в публичный Git-репозиторий, каталог установленного скилла или временный каталог. Если доступны только временные файлы или нет прав на постоянный путь, сообщи об ограничении и попроси постоянное место. Не меняй права существующих каталогов.

Разные компьютеры и эфемерные облачные сессии не разделяют этот журнал автоматически. Для общего архива нужно отдельно согласовать перенос или синхронизацию. Не создавай такую интеграцию молча.

## Формат и запись

Одна запись — отдельный UTF-8 JSON-файл. Имя вычисляется из `event_id`; повтор точно той же записи идемпотентен, конфликт с другим содержимым останавливается. Обязательно сохраняй тот же `event_id` при повторной попытке. Для новой задачи придумай устойчивый обезличенный `task_id`, для нового события — новый `event_id`. Для продолжения задачи используй прежний `task_id`. Одинаковый компонент из разных каталогов обозначай одной канонической исходной ссылкой, чтобы не раздробить статистику.

```bash
python3 /path/to/tool-finder/scripts/usage_log.py record \
  --event-id task-20261112-01-review-recommended \
  --task-id task-20261112-01 --category technical-writing \
  --tool-url https://github.com/Jho00/personal-harness/blob/main/skills/review-technical-text/SKILL.md \
  --kind skill --stage review --status recommended \
  --note 'Подходит для предпроверки технического текста'
```

Команда возвращает JSON с `result` (`recorded` или `already_recorded`) и путём. Для реального применения создай отдельное событие с `--status used --outcome success`, `partial` или `failed`. `rejected` означает отказ от кандидата. Для `recommended` и `rejected` не задавай `--outcome`.

Записывай лишь наблюдавшееся применение или явно сообщённый пользователем результат, отмечая источник в `note`. Использование на другом компьютере или в другом чате не наблюдается автоматически. Если задача продолжается, передай её исполнителю `task_id`, путь журнала и правило записи после фактического применения; это не разрешает передачу частных данных внешним агентам. Если продолжение не находится под твоим контролем, скажи, что результат можно записать при следующем обращении. Не создавай фиктивные `used` в конце подбора.

Не сохраняй полный промпт, частные документы, содержимое переписки, персональные данные и секреты. `category`, `stage` и `note` должны быть короткими обезличенными описаниями; URL — публичным источником без токенов. Скрипт не является автоматическим средством удаления чувствительных данных: проверь поля перед записью.

## Просмотр и новые сценарии

```bash
python3 /path/to/tool-finder/scripts/usage_log.py summary
```

Результат — JSON: `tools` сортируется по `used_tasks`, затем по URL; `events` содержит записи для самостоятельного разбора. `used_tasks` считает различные задачи, а не вызовы и не установки. Если в задаче один компонент применяли несколько раз, исход, категория и этап берутся из последнего события `used`; исходные события остаются в `events`. Поэтому для последовательностей и всех промежуточных неудач изучай `events`, а не только сводку.

Покажи повторяющиеся цепочки по `task_id`, объясни, какие записи их поддерживают, и предложи сценарий на обсуждение. Частота сама по себе не доказывает пользу.

При повреждённой записи или ошибке доступа скрипт завершится с ошибкой. Не удаляй и не переписывай журнал ради успешного отчёта; покажи ограничение и выясни состояние. При прерывании записи может остаться неполный файл: сначала проверь его, не повторяй с новым ID вслепую. Одновременный просмотр во время записи может потребовать повторного чтения после её завершения.
