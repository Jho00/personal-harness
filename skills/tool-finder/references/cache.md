# Кеш публичных репозиториев

Кеш экономит повторный обход дерева GitHub и поиск исходных файлов компонентов между вызовами. Он не кеширует поисковую выдачу, подбор под конкретную задачу, исходные файлы или разрешения. Python 3.9+ и стандартная библиотека; ничего не устанавливай ради кеша без согласия.

1. Обнаружь репозиторий через текущий источник и убедись, что он публичный. Перед обходом передай в `get` корневой HTTPS URL GitHub без параметров, фрагмента, пути к файлу или учётных данных. Регистр, конечный слеш и суффикс `.git` не влияют на ключ.
2. При `hit` используй сохранённые пути как кандидатов из снимка указанного коммита. Не обходи дерево повторно, если этого достаточно. Если путей не хватает для текущей задачи, углуби поиск. Отсутствие пути в снимке не доказывает, что компонента нет. Перед актуальной рекомендацией прочитай конкретный файл из текущей ветки или версии источника, а не только из сохранённого коммита; если специально рекомендуешь закреплённую версию, явно укажи её. Сверяй права, совместимость и всё, что зависит от текущего состояния. Не выдавай дату снимка за текущую онлайн-проверку.
3. При `miss` выполни обычный поиск. После успешного просмотра публичного исходника на известном коммите сохрани только проверенные относительные пути и типы компонентов. Не записывай пустой или неполный снимок, возникший из-за ошибки, неизвестной видимости или недоступного источника. Не сохраняй частные репозитории, содержимое файлов, секреты, данные пользователя или вывод по его задаче.
4. Если пользователь просит перепроверить без кеша, вызови `get --refresh` для нужных репозиториев, затем обнови снимок после успешной проверки. `unavailable`, `invalid` и отсутствие Python не блокируют подбор: работай без кеша. Для неподдерживаемых URL используй обычный просмотр источника.

Из корня установленного скилла:

```bash
python3 scripts/repo_cache.py get https://github.com/example/tools
python3 scripts/repo_cache.py get https://github.com/example/tools --refresh
python3 scripts/repo_cache.py put https://github.com/example/tools <<'JSON'
{"commit":"aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa","components":[{"kind":"skill","path":"skills/demo/SKILL.md"}]}
JSON
```

В примере SHA и путь условные. Допустимые типы: `skill`, `prompt`, `agent`, `tool`. Команды только читают и пишут локальные JSON-файлы, без сетевого доступа. Помощник проверяет формат URL, но не публичность репозитория: её нужно проверить до обращения к кешу. Снимок считается свежим 24 часа после записи; просроченный не используется и может быть заменён новой проверкой. Кеш располагается вне Git и отдельно от журнала, в `${XDG_CACHE_HOME:-$HOME/.cache}/personal-harness/tool-finder/repos/`, либо в каталоге из `TOOL_FINDER_CACHE_DIR` или `--cache-dir` (перед подкомандой). Не направляй кеш в каталог журнала или в общую папку. Между компьютерами и изолированными средами снимки автоматически не переносятся.
