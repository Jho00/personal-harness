# Personal Harness

Репозиторий переиспользуемых скиллов, сценариев и ролей для агентных клиентов. Скиллы можно устанавливать отдельно из Git. Пакеты объединяют компоненты в готовые наборы.

## Каталоги

| Каталог | Что хранить |
| --- | --- |
| `skills/` | Скиллы в формате Agent Skills вместе с их скриптами, справками и шаблонами. |
| `workflows/` | Сценарии с входными данными, шагами, используемыми ролями и скиллами, ожидаемым результатом. |
| `agents/` | Описания ролей, их ответственности и формата результата. |
| `packages/` | Состав устанавливаемых наборов и скрипты, которые нужны только полному набору. |
| `adapters/` | Форматы конфигурации и правила установки для конкретных клиентов. Для Codex используй `adapters/codex/`. |
| `evals/` | Примеры входных данных и критерии оценки результата скилла или сценария. |

## Добавление компонентов

- Для каждого скилла создай `skills/<name>/SKILL.md` с полями `name` и `description` в YAML-шапке. Значение `name` должно совпадать с именем каталога.
- Скрипты, которые нужны скиллу при отдельной установке, храни в его каталоге `scripts/`. Скрипты полного набора храни в `packages/<name>/scripts/`. В инструкции, которая вызывает скрипт, укажи относительный путь, зависимости, аргументы и ожидаемый результат.
- При сборке пакета включай выбранные скиллы вместе с их файлами. Для публикации в формате Agent Plugins используй `plugin.json` в корне пакета.
- Храни привязки к конкретному клиенту в его адаптере. При подключении роли к Codex размещай TOML в `.codex/agents/` проекта, где будет запускаться субагент.
- Удаляй `.gitkeep`, когда в том же каталоге появляется первый содержательный файл.
